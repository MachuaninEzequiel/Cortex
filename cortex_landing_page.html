01 // Definición Fundamental

¿Qué es Cortex?

Cortex no es un simple wrapper ni un plugin de chat. Es un Sistema Operativo Cognitivo diseñado específicamente para dotar a los agentes de software de memoria híbrida a largo plazo, disciplina arquitectónica y economía radical de contexto.

Motor de Memoria Dual Híbrida (Lexical + Vectorial)

Combina la precisión léxica sub-milisegundo de Tantivy (BM25) con la comprensión semántica profunda de vectores densos (FastEmbed). Un algoritmo de balanceo dinámico reasigna pesos según la especificidad de la consulta, permitiendo que el agente recupere identificadores de código exactos sin alucinaciones.

Query del Agente
→
BM25 Lexical (α=0.6)
+
Dense Vector (1-α)
→
Rank Fusion & Payload

TypeSafe JEV System One

Clasificador determinista ultrarrápido que actúa como el "Sistema 1" (pensamiento rápido) de Daniel Kahneman. Filtra salidas ruidosas de herramientas antes de contaminar la memoria episódica.

noul < 0.50 → Compact & Truncate
Distractor confidence: 0.94 → Prune

Gobernanza Triádica

Separa la cognición en tres pilares inquebrantables: State (especificaciones formales y ADRs), Ledger (registro inmutable de sesiones) y Strategy (supervisión por Autopilot).

Daemon Nativo en Rust con Cero Sobrecarga

Construido íntegramente en Rust con Tokio y SQLite embebido. Se ejecuta localmente sin requerir entornos virtuales pesados, sin latencia de red en las consultas de memoria interna (sync en 18ms, retrieval en 4ms) y con cero consumo en reposo.

✓ 0ms Cloud Overhead ✓ Concurrencia Tokio Async ✓ SQLite WAL Mode ✓ Tantivy Embedded Index
02 // Manual Práctico y Flujo de Trabajo

¿Cómo usar Cortex?

Cortex se integra fluidamente a través de dos canales: su potente CLI interactivo para desarrolladores y el estándar Model Context Protocol (MCP) con 32 herramientas para agentes autónomos.

Indexación Automática del Repositorio

Examina el árbol del proyecto, extrae árboles sintácticos (AST), actualiza el índice Tantivy y recalcula los embeddings en FastEmbed. Se ejecuta en menos de 20ms.

Terminal Bash 
# Sincroniza el código actual y genera la memoria vectorial + BM25
cortex sync

# Salida esperada:
# [INFO] Scanned 52 files (0 ignored).
# [OK] Built Tantivy index in 12.4ms.
# [OK] Vector embeddings updated in SQLite WAL.
# [INFO] Repository memory state: READY.

Inyección Quirúrgica de Contexto

Realiza una búsqueda híbrida rankeada y filtra distractores antes de devolver el payload formateado para el agente LLM.

Ciclo de Vida de Sesión con Memoria Episódica

Permite abrir, registrar checkpoints y cerrar sesiones de trabajo. Al abrir una nueva sesión, el agente recupera exactamente dónde quedó sin tener que releer todo el historial.

Terminal Bash 
# 1. Abrir sesión de trabajo
cortex session open --title "Desarrollo de landing page UI"

# 2. Guardar un punto de control con decisiones tomadas
cortex session checkpoint --summary "Componentes Bento Grid completados"

# 3. Cerrar sesión y compactar la memoria
cortex session close --handoff "Siguiente paso: integrar gráficos SVG interactivos"

03 // Justificación de Ingeniería

¿Por qué usar Cortex?

Los LLMs actuales sufren de cuatro cuellos de botella cognitivos fundamentales cuando interactúan con bases de código complejas. Cortex los resuelve de raíz.

1. Amnesia de Sesión

Al cerrar la terminal o terminar una conversación, el agente olvida absolutamente todo el conocimiento tácito acumulado.

Sin Cortex
El programador debe reescribir prompts kilométricos en cada sesión (5,000+ tokens gastados solo en contexto inicial repetido).
Con Cortex JEV
El Ledger episódico restaura el estado mental exacto y las tareas pendientes con una llamada de 180 tokens.

2. Explosión Cuadrática de Tokens

En sesiones largas, el historial acumula salidas de comandos enteras (`git log`, tests, builds) escalando en $O(N^2)$.

Sin Cortex
En el turno 18 se acumulan 31,756 tokens y costos exponenciales por arrastrar logs inútiles en cada request.
Con Cortex JEV
La compactación automática trunca salidas no informativas a 14,856 tokens (-53.2%), aplanando la curva a $O(N)$ lineal.

3. Deriva Arquitectónica (Drift)

A medida que la sesión avanza, los agentes "inventan" clases de CSS, violan directrices o agregan dependencias no autorizadas.

Sin Cortex
61.1% de cumplimiento. El agente inventa estilos ad-hoc y rompe la consistencia del sistema de diseño.
Con Cortex JEV
100% de cumplimiento en todos los turnos. Las reglas de diseño (ADR) se imponen como invariantes inmutables.

4. Desperdicio en Razonamiento (Thinking)

Cuando el contexto está saturado de ruido y archivos distractores, el LLM gasta miles de tokens intentando reconciliar contradicciones.

Sin Cortex
4,110 tokens de thinking desperdiciados en reflexiones circulares sobre logs y archivos irrelevantes.
Con Cortex JEV
1,940 tokens de thinking (-52.8%). El modelo razona de forma directa, rápida y sin titubeos.

07 // Respuestas Rápidas

Preguntas Frecuentes

Todo lo que necesitas saber antes de desplegar Cortex en tu entorno local o de empresa.

Cortex corre 100% de manera local. Su motor Tantivy de búsqueda léxica, SQLite para la persistencia del Ledger y FastEmbed para representaciones vectoriales operan en el hardware de tu máquina sin transferir tu código a servidores externos.
Mediante el estándar abierto Model Context Protocol (MCP). Solo debes añadir la configuración de Cortex a tu archivo claude_desktop_config.json, antigravity.json o settings.json de Cursor. Las 32 herramientas quedan expuestas automáticamente al agente sin requerir cambios en tu código fuente.
Porque un agente "Raw" opera a ciegas: no carga reglas de diseño, ni memoria previa ni contratos. Sin embargo, comete violaciones inmediatas (inventa código). En el Turno 9 (Punto de Cruce), el agente Raw empieza a arrastrar el historial de herramientas acumulado y Cortex se vuelve estrictamente más barato en cada turno subsiguiente, finalizando con un ahorro del 53.2%.
TypeSafe JEV evalúa la utilidad informativa de cada salida de herramienta anterior. Si un log de test o un volcado de directorio tiene una probabilidad de relevancia $noul < 0.50$, lo trunca a un marcador semántico conciso. Esto impide que el LLM sufra sobrecarga atencional en sus ventanas de contexto.
