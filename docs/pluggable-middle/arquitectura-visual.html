01 El principio rector

Cortex deja de imponer un protocolo y pasa a envolver un workflow. Observa entrada (spec) y salida (estado verificable del repo) sin requerir cooperación del middle.

1. La spec es el contrato. Lo que el sync produce es la fuente de verdad sobre qué se va a hacer.
2. El diff es el resultado. El estado verificable del repo (diff + tests + commits) es la fuente de verdad sobre qué se hizo.
3. El medio es opaco. Cortex no necesita saber cómo se produjo el diff. Solo necesita comparar diff vs spec.

03 Los tres modos de operación

La calidad degrada con gracia. No se rompe.

🟢 Managed DISCIPLINA MAX

middle = cortex-SDDwork
Contrato disponible
Spec + diff + checkpoints estructurados
Calidad session note
Máxima — claims verificados + contexto explícito
Para quién
Usuarios sin tooling propio, o que quieren disciplina forzada
Fricción
Alta (curva de aprendizaje del SDDwork)

🟡 Observed BALANCE

middle = agente del usuario + hooks
Contrato disponible
Spec + diff + checkpoints parciales
Calidad session note
Alta — diff cross-checked con eventos del IDE
Para quién
Cursor + Composer, Claude Code con skills custom, Pi
Fricción
Baja (instalás hook una vez, listo)

🔵 BYO LIBERTAD MAX

middle = lo que sea
Contrato disponible
Spec + diff (cero checkpoints)
Calidad session note
Buena — todo reconstruido desde diff observable
Para quién
Cualquiera. Vibe coding, manual, otro agente
Fricción
Mínima (solo `create-spec` y `finish-session`)

06 Algoritmo de reconstrucción (8 pasos)

Cómo el documenter sintetiza todo desde una Session, sin necesidad de YAML cooperativo del middle.

1

Cargar contexto

session = read(.cortex/sessions/<id>.yaml) · spec = read(session.spec_path) · checkpoints = session.checkpoints (puede estar vacío en BYO)

2

Computar diff observable

diff = git diff session.start_commit..HEAD · files_touched = parse_diff(diff) · end_commit = git rev-parse HEAD

3

Ejecutar verification hooks

Para cada hook del spec: ejecutar con timeout, capturar exit code + output. Guardar VerificationHookResult.

4

Cross-check contra spec

in_scope · out_of_scope (scope drift) · unimplemented (estaba en spec, no se tocó)

5

Detectar contradicciones (memoria)

Buscar en memoria semántica decisiones previas que choquen con el diff actual. Marcar conflictos.

6

Construir AgentHandoff sintético

verified_claims (del diff/tests) · unverified_claims (criterios sin probar) · artifacts_produced · suggested_adr (criterios 3/3)

7

Decidir status sugerido

Todos los hooks required pasan + nada unimplemented → CLOSED. Algún hook required falla o queda trabajo → HANDOFF.

8

Persistir y cerrar

Si auto: write_session_note + write_adrs + update CONTEXT.md + index memory + session_close. Si interactive: mostrar draft, esperar [A/E/H/C].

07 Documenter: Auto vs Interactive

El algoritmo es el mismo. Cambia solo lo que pasa al final: persistir directo o pedir confirmación al usuario.
