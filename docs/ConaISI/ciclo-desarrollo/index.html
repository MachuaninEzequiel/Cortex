🥪 El Ciclo Sandwich Canónico (Fases 0 a 7)

La estructura tripartita de Cortex: Top de Sincronización, Middle de Implementación Directa y Bottom de Documenter Inmutable

Fase 0: Detección & Host Isolation Bootstrap

HostDetector inspecciona el proceso padre. Si detecta Google Antigravity, activa el escudo ToS estricto: bloquea llamadas de Anthropic o claves directas y activa solo Gemini Pro/Flash. En Pi o Cursor, expone OpenRouter libremente.

crate: cortex-setup · HostPolicyShield · zero-trust
Fase 1: Utterance Gate (SystemOne) Micro-Reflejo

Ante el primer prompt del usuario, Utterance Gate clasifica en <10ms si la intención es trivial (chat/status) o de desarrollo sustancial (work: implement, refactor). Si es sustancial, exige apertura de sesión para asegurar trazabilidad.

crate: cortex-judgement · Kahneman System 1 · <10ms latency
Fase 2: Top del Sandwich (Sync & Apertura) Top Sandwich

Invocación obligatoria de cortex_session_open o cortex_sync_ticket. Se crea el SessionRecord en .cortex/sessions/, se congela el commit base de git (start_commit=HEAD) y se ancla la especificación formal del trabajo.

tools: cortex_session_open, cortex_sync_ticket, cortex_create_spec
Fase 3: Ruteo Dinámico de Subagentes Rebuild Menu

cortex_session_status evalúa el estado vivo de la sesión. Sin checkpoints previos, recomienda al Architect (cortex-code-designer). Con diseño listo, despacha al Implementer. Model Router selecciona el mejor modelo con confianza ≥ 0.85.

tools: cortex_session_status · purpose: ModelRouting · score 0..2
Fase 4: Recuperación Híbrida & Search Squeeze Context Pack

cortex_context fusiona búsqueda léxica BM25 y vectorial V3 con algoritmo RRF (k=60). Tiered Memory atenúa documentos históricos/archivo al 20% de peso. Search Squeeze poda distractores y ruido cognitivo.

tools: cortex_context, cortex_search · RRF k=60 · Tier archive 0.2
Fase 5: Checkpoints & Verification Gate Quality Audit

Durante la codificación se registran checkpoints con claims específicos y archivos tocados. Antes de cerrar, cortex_verify_session_claims audita los tests y el git diff. Si hay contradicciones o fallas, el cierre se rechaza.

tools: cortex_session_checkpoint, cortex_verify_session_claims
Fase 6: Bottom del Sandwich (Documenter) Bottom Sandwich

Al terminar la tarea, el orquestador tiene prohibido cerrar sin documentar. Invocación de cortex_finish_session: el subagente Documenter analiza el diff completo, escribe las notas de sesión y redacta el nuevo ADR canónico en el Vault.

tools: cortex_finish_session, cortex_documenter_briefing, cortex_write_doc
Fase 7: Filtro worth_remembering & Sellado Persistencia

SystemOne evalúa los aprendizajes de la sesión: solo persiste soluciones a problemas reales o decisiones de arquitectura, eliminando ruido efímero. Se guardan en .cortex/memory/ (JSONL), se actualiza vectors.v3.bin y se sella la sesión.

tools: cortex_session_close · evaluate_worth_remembering · vectors.v3
