# F5 — `/cortex-team` (auto-spawn portable de terminales)

Quinta y última fase. Convierte el problema más ingrato del multi-terminal
(abrir N terminales con N comandos distintos en N ventanas distintas) en
**un slash command que elige un preset y dispara N spawns en paralelo**,
con detección cross-OS de terminal multiplexer y fallback universal al
clipboard.

> Estado: ✅ **completa**

## Lo que entrega

### `cortex-team.ts` (nueva extension)

Registra dos slash commands:

- **`/cortex-team`**: selector de preset + spawn de terminales.
- **`/cortex-team-status`**: dump rápido de `team.json` (debug helper).

#### Presets disponibles

Ordenados por uso esperado:

| ID | Label | Roles que abre |
|---|---|---|
| `deep_full` | Deep Track full | designer + implementer + documenter |
| `deep_with_audit` | Deep Track + audit | designer + implementer + security + test-verifier + documenter |
| `design_pair` | Design pair | designer + implementer |
| `audit_pair` | Audit pair | security + test-verifier |
| `explorer_only` | Explorer (análisis read-only) | explorer |
| `documenter_only` | Documenter observer (escuchar in-flight) | documenter |

El selector recalcula contextualmente qué roles del preset están ya
conectados y solo spawnea los que faltan. Si todos están conectados, el
selector no hace nada y avisa.

#### Detección de terminal por OS

| Plataforma | Estrategia 1 | Estrategia 2 (fallback) |
|---|---|---|
| Windows | `wt.exe` (Windows Terminal) | `cmd.exe /c start cmd.exe /K` |
| macOS | `osascript` → Terminal.app | clipboard |
| Linux (en tmux) | `tmux split-window -h` | (probar gráficas) |
| Linux (gráfica) | alacritty → kitty → gnome-terminal → konsole → xterm | clipboard |

Todas las invocaciones de spawn usan `{detached: true, stdio: "ignore"}`
+ `.unref()` para que la hija sobreviva al master sin pipearle stdin/out.

#### Fallback universal: clipboard

Cuando ninguna terminal del SO se detecta o el spawn falla, los comandos
se copian al clipboard usando:

- Windows: `clip`
- macOS: `pbcopy`
- Linux (X11): `xclip` o `xsel`
- Linux (Wayland): `wl-copy`

El usuario pega en sus terminales preferidas y listo. UX sigue siendo
"un click + pegar" en vez de "copiar 5 comandos a mano del cockpit".

#### Tracking en `team.json`

Cada spawn exitoso se anota en `<workspace>/.pi/agent-sessions/team.json`:

```json
{
  "master_pid": 12345,
  "session_id": "2026-05-28_login-refactor",
  "cwd": "/path/al/proyecto",
  "spawned": [
    { "role": "designer", "spawned_at": "2026-05-28T12:01:23Z", "mechanism": "windows-terminal" },
    { "role": "implementer", "spawned_at": "2026-05-28T12:01:23Z", "mechanism": "windows-terminal" }
  ]
}
```

El archivo se merge-actualiza si ya existía (suma nuevos spawns al final
del array `spawned`). Útil para:
- `/cortex-team-status` muestra estado actual.
- Iteraciones futuras: shutdown coordinado (escribir `shutdown: true`
  y que las hijas lo detecten).
- Diagnóstico de bugs.

### Integración con F2 y F4

Actualizaciones quirúrgicas en las extensiones anteriores ahora que
`/cortex-team` existe:

- **F2 (`cortex-autopilot.ts`)**:
  - Hotkey `:t` cambia de `{kind: "notify", text: "F5 pendiente"}` a
    `{kind: "slash", command: "/cortex-team"}`.
  - El texto del hotkey help (`:?`) refleja la nueva semántica.
- **F4 (`cortex-panel.ts`)**:
  - El `ActionItem` `team_spawn` pierde el flag `pendingFeature: "F5"`.
  - Al seleccionarlo, el notify se actualiza para apuntar al nuevo
    comando real (el dispatch sigue siendo notify hint porque no hay
    API documentada para invocar slash programáticamente).

## Decisiones tomadas

| Decisión | Elección | Justificación |
|---|---|---|
| Selección | **Preset único** (no multi-select) | API de Pi `ctx.ui.select` retorna un solo string. Multi-select requeriría `SettingsList` con focus routing custom — overhead alto para poco beneficio. Los 6 presets cubren los casos. |
| Spawn detached | `unref()` + `detached: true` | Las hijas sobreviven al master. Si master muere, las hijas siguen vivas y la red se reconfigura sola. |
| Clipboard fallback | Sí, universal | Garantiza que el flow nunca queda "trabado" — siempre hay manera de continuar aunque no detecte terminal. |
| Tracking en team.json | Sí | Necesario para coordinar acciones futuras (cierre, diagnóstico). |
| Coordinated shutdown | **NO en F5** | Las hijas detectan sesión cerrada vía polling del session.lock (F1). La señal explícita en team.json queda como mejora futura. |
| Guard "solo master" | Sí | Decisión explícita del usuario (vista limitada para workers). Workers que tipean /cortex-team reciben notify warning. |

## Contratos con otras fases

### Lee del singleton (F1)
- `cwd`, `sessionId`, `isMaster`, `peers` (para filtrar conectados).

### Escribe al filesystem
- `<cwd>/.pi/agent-sessions/team.json`.

### Activado por F2 hotkey `:t` y F4 action `team_spawn`
- Ambos hacen transform/hint al slash command `/cortex-team`.

### Spawnea procesos que arrancan con `just role-<role>`
- Esto requiere que el `justfile` del bundle tenga esas recetas. El
  bundle 2.5+net ya las tiene (`just role-designer`, etc.).

## Gaps abiertos (no bloqueantes)

1. **Coordinated shutdown**: si master cierra la sesión, las hijas se
   enteran vía polling de `session.lock` (F1) pero no reciben señal
   explícita. Solución: en F2 (autopilot) o en cortex-net, agregar un
   poll a `team.json.shutdown` y mostrar notify "master cerró sesión,
   podés cerrar con Ctrl+D". 1-2 horas de trabajo.
2. **PID de las hijas**: hoy `team.json` no guarda PID porque el
   spawn detached no devuelve PID confiable cross-platform. Tracking
   por rol + cwd + session_id es suficiente para la mayoría de usos.
3. **Re-spawn de rol ya conectado**: el selector lo detecta y lo
   excluye, pero el preset entero se acepta — si elegís
   "design_pair" y designer está conectado, solo se abre implementer.
   Comportamiento correcto pero podría sorprender. Iteración futura:
   mostrar el delta antes de spawnear con un confirm.
4. **Múltiples ventanas Windows Terminal**: el flag `-w 0` mete las
   hijas en la ventana actual del usuario. Si querés ventana separada
   por hija, cambiar a `-w new` o `wt.exe new-tab`.

## Cómo probarlo (manual)

### En Windows con Windows Terminal:

1. `just cortex` en T1 (master).
2. Activar agent del medio (ej. `/system cortex-SDDwork`).
3. Tipear `/cortex-team` o `:t`.
4. Elegir "Deep Track full".
5. Ver 3 tabs nuevas en Windows Terminal con designer, implementer,
   documenter.
6. T1 cockpit muestra los 3 peers conectándose en vivo (F3 push events).

### En Linux con tmux:

1. Dentro de `tmux`, abrir T1 con `just cortex`.
2. Repetir 2-4 de arriba.
3. Las hijas aparecen como `split-window` panes en la misma ventana
   tmux.

### Sin terminal detectable (raro):

1. `just cortex` en alguna terminal exótica.
2. `/cortex-team`, elegir preset.
3. Notify warning "no pude spawnear automáticamente; comandos copiados
   al clipboard".
4. Pegar en terminales nuevas.

### Diagnóstico:

- `/cortex-team-status` muestra `team.json` actual.
- `cat .pi/agent-sessions/team.json` para ver el JSON crudo.

## Cierre del overhaul UX

F5 completa el plan F1-F5. Resultado integrado:

1. **F1 (Cockpit + singleton)**: estado siempre visible arriba +
   3 slots de status bar abajo.
2. **F2 (Autopilot)**: hotkeys virtuales `:n :t :d :r :m :l :?` +
   gates con warning + sugerencias contextuales.
3. **F3 (Bonus net)**: status pings (idle/busy/observe), tool
   `cortex_net_broadcast`, eventos push (sin polling).
4. **F4 (Panel `/cortex`)**: TUI modal grande con vista master/worker
   y todas las acciones en un lugar.
5. **F5 (`/cortex-team`)**: auto-spawn cross-OS de terminales con
   fallback universal.

UX final: el usuario tipea su tarea, sync abre la sesión, tipea
`/cortex-team` y elige "Deep Track full", el sistema spawnea 3
terminales, el cockpit muestra el progreso, manda mensajes con
`/cortex` → "Mandar mensaje" → SelectList, y cierra con `:d` → notify
para cambiar a documenter. Cero memoria de comandos.
